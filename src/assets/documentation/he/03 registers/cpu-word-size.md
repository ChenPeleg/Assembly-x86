# גודל האוגרים

מעבדים ישנים עבדו עם ערכים של 16 ביטים, ומעבדים חדשים יותר עם 32 ביטים. האמולטור הזה מדמה מעבד של 32 ביטים, ולכן לכל אוגר כללי יש שם של 32 ביטים, וגם חלקים קטנים יותר שאפשר להשתמש בהם בנפרד.

| מעבד     | גודל מילה |
|---------|-----------|
| 8086    | 16 ביטים   |
| 80286   | 16 ביטים   |
| 80386   | 32 ביטים   |
| 80486   | 32 ביטים   |
| Pentium | 32 ביטים   |

## החלקים של אוגר

`EAX` הוא הערך המלא של 32 ביטים. `AX` הוא 16 הביטים התחתונים שלו, `AL` הוא 8 הביטים התחתונים, ו-`AH` הוא הביטים 8 עד 15.
אותו דבר נכון ל-`EBX`, `ECX` ו-`EDX`. ל-`ESI` ול-`EDI` יש חלק של 16 ביטים (`SI`, `DI`), אבל אין להם חלקים של 8 ביטים.

```shell
section .text
    MOV EAX, 0
    MOV AL, byte 255 ; fills only the lowest byte
    MOV AH, byte 1   ; fills the second byte
    INT 1          ; prints 511
```
<!-- -console -memory cpu -->

כתיבה ל-`AL`, ל-`AH` או ל-`AX` לא משנה את שאר הבתים של `EAX`.

```shell
section .text
    MOV EAX, 0x11223344
    MOV AX, word 0  ; EAX is now 0x11220000
    MOV BL, byte 7  ; only the low byte of EBX changes
```
<!-- -console -memory cpu -->

<!-- info -->
> במעבדים אמיתיים של 64 ביטים יש גם `RAX`, `RBX`, ... באמולטור הזה אין אוגרים של 64 ביטים.

<!-- notice -->
> מספר רגיל הוא ברוחב 32 ביטים, ולכן עבור אוגרים קטנים יותר צריך לציין את הגודל: `byte 5` או `word 5`.

<strong>נסו בעצמכם:</strong> שנו את `MOV AX, 0` ל-`MOV EAX, 0` וראו איך האוגר כולו מתאפס.
